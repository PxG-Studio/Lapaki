# NIST SP 800-53 Rev. 5 — Healthcare Data Pipeline Control Mapping

> **Standard:** NIST Special Publication 800-53, Revision 5 (September 2020)  
> **COBIT alignment:** MEA03 (Managed Compliance with External Requirements)  
> **Applicable systems:** All pipeline components containing or processing ePHI

---

## Overview

NIST SP 800-53 Rev. 5 provides a comprehensive catalog of security and privacy controls for federal information systems, widely adopted in healthcare as a companion to HIPAA compliance. This document maps the most relevant control families to the health data architecture pipeline.

---

## Control Family Mapping

### AC — Access Control

| Control | Title | Pipeline Application |
|---------|-------|---------------------|
| AC-1 | Policy and Procedures | Documented RBAC policy; see `governance/access-control-matrix.md` |
| AC-2 | Account Management | Automated provisioning/deprovisioning; 30/60/90-day review cycle |
| AC-3 | Access Enforcement | Minimum necessary principle; role-based query scope enforcement |
| AC-4 | Information Flow Enforcement | Unidirectional data flow: EHR → DW → CDM → De-ID (no reverse flow of PHI) |
| AC-6 | Least Privilege | Researchers receive query-only access; no direct database write access |
| AC-17 | Remote Access | VPN + MFA required for all remote access to PHI-containing systems |
| AC-19 | Access Control for Mobile Devices | MDM enrollment required; remote wipe capability |

### AU — Audit and Accountability

| Control | Title | Pipeline Application |
|---------|-------|---------------------|
| AU-2 | Event Logging | Log: login/logout, data access, data export, admin actions, failed auths |
| AU-3 | Content of Audit Records | Timestamp, user ID, event type, object identifier, outcome |
| AU-6 | Audit Record Review, Analysis, Reporting | Weekly automated log review; monthly manual analysis |
| AU-9 | Protection of Audit Information | Logs stored in append-only, write-protected storage |
| AU-12 | Audit Record Generation | All systems generate logs in SIEM-compatible format (CEF/JSON) |

### IA — Identification and Authentication

| Control | Title | Pipeline Application |
|---------|-------|---------------------|
| IA-2 | Identification and Authentication (Org. Users) | Unique user IDs; MFA required for all PHI system access |
| IA-5 | Authenticator Management | Password complexity ≥12 characters; MFA tokens rotated annually |
| IA-8 | Identification and Authentication (Non-Org. Users) | External partner authentication via federated identity (SAML 2.0 / OIDC) |

### IR — Incident Response

| Control | Title | Pipeline Application |
|---------|-------|---------------------|
| IR-1 | Policy and Procedures | See `governance/incident-response-plan.md` |
| IR-4 | Incident Handling | 6-phase response: Detection, Containment, Assessment, Notification, Recovery, Review |
| IR-5 | Incident Monitoring | 24/7 SIEM monitoring; automated alerting for threshold breaches |
| IR-6 | Incident Reporting | Internal: 1 hour to Security Officer; External: 60-day HIPAA deadline |
| IR-8 | Incident Response Plan | Annual tabletop exercise; post-incident update |

### RA — Risk Assessment

| Control | Title | Pipeline Application |
|---------|-------|---------------------|
| RA-3 | Risk Assessment | Annual risk analysis per 45 CFR §164.308(a)(1); covers all 14 pipeline nodes |
| RA-5 | Vulnerability Monitoring and Scanning | Quarterly vulnerability scans; monthly for internet-facing systems |
| RA-7 | Risk Response | Risk treatment plan per COBIT EDM03 |

### SC — System and Communications Protection

| Control | Title | Pipeline Application |
|---------|-------|---------------------|
| SC-7 | Boundary Protection | Network segmentation: PHI systems on isolated VLAN; DMZ for federated access |
| SC-8 | Transmission Confidentiality and Integrity | TLS 1.3 for all ePHI transmission |
| SC-12 | Cryptographic Key Establishment | HSM for key management; annual key rotation for data-at-rest encryption |
| SC-28 | Protection of Information at Rest | AES-256 encryption for all PHI-containing data stores |

### SI — System and Information Integrity

| Control | Title | Pipeline Application |
|---------|-------|---------------------|
| SI-2 | Flaw Remediation | Critical patches: 72 hours; High: 30 days; Medium: 90 days |
| SI-3 | Malicious Code Protection | EDR on all endpoints; anti-malware on all servers |
| SI-7 | Software, Firmware, and Information Integrity | Hash verification of CDM data exports; signed pipeline artifacts |
| SI-12 | Information Management and Retention | Per retention schedule in `governance/data-governance-policy.md` |

### PM — Program Management

| Control | Title | Pipeline Application |
|---------|-------|---------------------|
| PM-25 | Minimization of Personally Identifiable Information | De-identification by default; data minimization at every CDM stage |
| PM-27 | Privacy Reporting | Annual privacy report to executive leadership |
